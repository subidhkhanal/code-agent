Terminal coding agent · Python

A coding agent that checks its own edits before you see them.

code-agent indexes your repository locally, finds the code a request is about, and has an LLM propose focused edits. Every edit must match exactly one place in a file the model has read, and is validated in a hidden git worktree (lint, type check, the tests that cover it) before you review a diff. Commands run only under a code-enforced approval policy. A headless mode runs the same engine in a locked-down container.

Fixing a bug, end to end

The first edit has a typo. Pyright and a regression test catch it in the shadow worktree, the model fixes it, the tests pass, and only then is the diff shown. Then it's applied and undone.

Recorded with asciinema in a container. The model's replies are scripted so the recording is reproducible; everything else is the real CLI with real ruff, pyright and pytest.

How it works

One engine behind two front ends: an interactive chat, and a headless runner for containers.

Index locally

tree-sitter chunks functions, class summaries and methods. BM25 (SQLite FTS5) and vectors (sqlite-vec, on-device ONNX embeddings) live in one file. Only changed chunks are re-embedded.

Retrieve within a budget

A cheap model rewrites the request into queries. Symbol, keyword and vector search are fused with RRF, called code is added as signatures, and everything is fit to a token budget.

Stream focused edits

The model writes SEARCH/REPLACE blocks, parsed as they stream. Fast Apply requires a unique match (exact → whitespace → fuzzy ≥ 0.9) in a file that hasn't changed since the model read it.

Validate in a shadow worktree

Edits land in a hidden git worktree first. Ruff, pyright and targeted tests run there, and only new problems count. Failures go back to the model for up to 3 fix rounds.

Approve by policy, in code

Commands are classified by code, not the model: read-only, test/lint, or privileged (asks every time). No shell, no API keys in the environment, killable process trees.

Review, apply, undo

You see the diff (per file if you like) with any remaining diagnostics. Accepted changes are written atomically, and agent undo refuses to clobber edits you made afterwards.

Architecture

The CLI is thin: the engine emits events and takes an injected approver and reviewer, so headless mode (and a future IDE extension) reuse it unchanged.

Security: rules in code, not in the prompt

The test suite scripts a fully compromised model that obeys instructions planted in a repo: curl | sh, read .env, edit git hooks and files outside the repo, grant itself permanent approval. Code has to stop all of it.

Reads of sensitive or out-of-repo paths0

Planted secrets in any request to the LLM or in logs0
Stale edit applied over the user's changenever
Cancel during a commandtree killed
Honest limits: in interactive mode an approved command runs with your own permissions, since there's no OS sandbox on a laptop. Headless mode is where isolation comes from Docker: internal network behind an allowlisting egress proxy, non-root, read-only root filesystem, resource limits.

Try it

Needs Python 3.12 and a Gemini API key. Config lives in your home directory, never in the repo.

# install
pipx install git+https://github.com/subidhkhanal/code-agent
export GEMINI_API_KEY=...        # PowerShell: $env:GEMINI_API_KEY = "..."
agent models                     # pick models, add them to ~/.config/code-agent/config.toml

# use
cd your-python-repo
agent index
agent chat
